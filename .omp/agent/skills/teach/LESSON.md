Lesson = primary vehicle for knowledge transfer + skill acquisition. Each lesson:

- Guided walkthrough: AI leads user start⇒finish, explanation + context at every step; user follows + imitates, not a command list to execute
- Immediate check after each knowledge chunk (blockquote/callout): user must produce an answer ⇒ verifies understanding, guarantees tangible cumulative gain
- Self-contained: opening states value, mission connection, prerequisites ⇒ enables independent study + later review

Every lesson ends with a `## Learning links` section listing:
- relative paths to other lessons + reference documents
- one primary external source to read or watch: highest-quality, most trustworthy resource on topic

## Philosophy
Deep learning needs:
- Knowledge: from high-quality, high-trust resources
- Skills: highly-relevant interactive lessons devised by you, based on knowledge
- Wisdom: interacting with other learners + practitioners

Until `RESOURCES.md` well-populated: focus on finding high-quality resources for knowledge. NEVER trust parametric knowledge.

> Some topics need more skills than knowledge (theoretical physics ⇒ knowledge-based; yoga ⇒ skills-based).

## Knowledge
Lessons designed around a skill to learn; lesson knowledge = only what that skill requires. Present knowledge first, then guide practice of the skill's steps.

Gather knowledge from trusted resources; track in `RESOURCES.md`. Litter lessons with citations: external links backing every claim ⇒ trustworthiness.

For knowledge acquisition, difficulty is the enemy: eats working memory needed for understanding.

## Skills
Knowledge = acquisition; skills = durability + flexibility. Make knowledge stick.

For skill acquisition, difficulty is the tool: effortful retrieval builds storage strength. Lesson = hands-on guide, not lecture: leads practice steps in order; AI answers questions during practice, never examines user live.

User judges own progress:
- practice steps have observable outcomes ⇒ user sees success/failure themselves
- prediction-vs-actual checkpoints inline, at point each chunk taught, formatted per [Skills](#skills); state predict-verify-compare ritual in prose at most once per lesson, never as callout banner
- checkpoint answers never shown before user answers, or prediction meaningless

Checkpoint answers: each exactly the same word count (characters too, if possible). No formatting clues.

## Acquiring Wisdom
Wisdom from true real-world interaction: testing skills outside the learning environment.

Question requiring wisdom: default = attempt to answer, but ultimately delegate to a **community**.

Community = place (online/offline) to test skills in the real world: forum, subreddit, real-world class (budget permitting), local interest group.

Find high-reputation communities user can join. User prefers not to join a community ⇒ respect it.

## ZPD
Zone of proximal development (ZPD): user always feels challenged 'just enough'.

User may specify exact thing to learn. If not, figure ZPD by:
- reading `learning-records/`
- figuring right thing to teach from mission
- teaching most relevant thing that fits in ZPD

## Fluency vs Storage
Two learning types:
- Fluency strength: in-the-moment retrieval of knowledge
- Storage strength: long-term retention of knowledge

Fluency ⇒ illusory mastery; storage strength = real goal. Design lessons for long-term retention via desirable difficulty:
- retrieval practice (recall from memory)
- spacing (distributing practice over time)
- interleaving (mixing related but different topics; skills practice only)
