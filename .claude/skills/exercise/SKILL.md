# 练习技能

核心原则：**不只看文字，必须动手写代码。** 无论概念多简单，都应产出有明确验证标准的结构化练习。

## 练习模式

根据用户需求和场景，选择以下三种模式之一：

| 模式 | 适用场景 | 产出物 |
|------|----------|--------|
| **独立练习题** | 学习新概念（设计模式、并发、算法、语言特性），不依赖现有项目 | 测试代码 + 骨架代码 + 参考解答 |
| **删除-重写练习** | 用户项目中有现成代码，但希望重新实现以加深理解 | 项目中的删除标记 + 原文件备份 + 对照检查清单 |
| **概念问答** | 需要深度理解概念、区分相似概念、或无法用代码自测的理论问题 | 问题清单 + 参考答案 + 自评标准 |

模式选择优先级：如果用户明确指向项目中的某段代码 → 删除-重写练习；如果用户想练手但不涉及项目 → 独立练习题；如果概念过于抽象或需要辨析 → 概念问答。

## 前置研究

生成练习前必须完成：

1. 搜索用户 Obsidian 笔记（`~/obsidian/notes`），查找该主题的现有笔记
2. 阅读相关笔记，了解用户当前深度——不练习已掌握的内容
3. 在练习 README 中引用笔记，连接新旧知识
4. 综合决定练习模式与难度：结合用户意愿、概念复杂度、笔记深度、项目关联程度。若关联项目代码则优先删除-重写练习；否则按概念难易和笔记情况选择基础/进阶练习或概念问答
5. 指出笔记中的具体遗漏点作为练习目标

## 输出结构

练习文件放在 `.claude/exercises/<主题slug>/`，主题 slug 使用 kebab-case。

### 独立练习

```
.claude/exercises/<主题slug>/
├── README.md              # 练习说明、学习目标、提示
├── <测试文件>              # 测试代码
├── <骨架文件>              # 骨架代码
└── solution/
    ├── README.md          # 解答说明——解释为什么这样做
    └── <解答文件>           # 完整的参考实现
```

多任务渐进式练习：

```
.claude/exercises/<主题slug>/
├── README.md              # 总体说明与学习路径
├── task-01-<子主题>/
│   ├── README.md
│   ├── <测试文件>
│   ├── <骨架文件>
│   └── solution/
│       └── ...
├── task-02-<子主题>/
│   └── ...
```

### 删除-重写练习

直接操作项目文件，同时保留原文件作为参考：

```
.claude/exercises/rewrite-<模块名>/
├── README.md # 说明删除范围、重写目标、对照检查清单
└── backup/ # 备份原文件
```

### 概念问答

```
.claude/exercises/<主题slug>-qa/
├── README.md # 说明问答主题、学习目标、自评标准
├── questions.md # 问题列表（用户作答区域）
└── answers.md # 参考答案（包含深度解析、常见错误）
```

## 练习模板

所有模式的练习文件 `README.md` 均使用以下通用模板，根据模式选择填写对应章节：

```markdown
# [概念名称]练习

> 对应笔记：[笔记文件名](~/obsidian/notes/路径) — 笔记已有的内容和遗漏点

## 学习目标

- [具体、可验证的目标——不是「理解 X」而是「实现能做 Y 的 X」]

## 前置知识

- [来自用户笔记的概念，建议先复习]

## 任务说明

[清晰描述要做什么]

### 独立练习题专用
- 验证方式：运行 `[命令]`，测试用例见 [测试文件路径或直接列出]
- 起步代码：[骨架文件路径]，已提供 [X]，你需要实现 [Y]

### 删除-重写练习专用
- 原代码位置：[项目路径]
- 删除内容：[函数/类/行号范围]，格式为 `备份文件相对路径:行号`
- 对照检查：对比备份 `backup/` 或运行原有测试 `[命令]`

### 概念问答专用
- 回答问题（写在 `questions.md` 中）：
  1. [问题1]
  2. [问题2]
- 自评标准：见 answers.md

## 要求
- [ ] [具体要求]
- [ ] [边界条件要求]

## 提示（如需帮助）
- [提示1]
- [提示2]
```

## 解答生成与自审查

生成参考解答时必须执行自审查：

1. 先编写解答代码和解答说明
2. **启动 agent 审查解答**：用独立 agent 验证解答的正确性、完整性和可理解性
3. 修复审查发现的问题

## 引导原则

用户练习过程中遇到问题时，**不直接给出答案**，而是引导思考：

- **编译错误**：分析错误信息，指出类型/语法问题出在哪一行，让用户自己修正
- **逻辑错误**：描述预期行为与实际行为的差异，问「当输入是 X 时，你的代码会输出什么？」
- **不会做**：拆解问题，先问用户对哪个子问题有思路，逐步引导
- **请求直接看答案**：先给出提示，鼓励再试一次；用户坚持时再提供解答

## 练习后流程

1. 用户告知完成练习
2. 根据模式进行评估：

   **独立练习题**：
   - 正确性：是否满足所有要求
   - 设计：是否有更好的写法
   - 边界条件：是否处理了 edge case
   - 笔记关联：是否填补了笔记中的知识缺口

   **删除-重写练习**：
   - 与原代码对比：逻辑等价性、遗漏边界、代码风格
   - 是否引入新 bug
   - 是否能进一步优化原代码（如果目标不是完全复刻）

   **概念问答**：
   - 准确性：概念理解是否正确
   - 深度：是否只是表面复述
   - 例证：能否给出恰当例子

3. 给出针对性反馈——做得好的点、可改进的点
4. 鼓励用户添加或更新对应的笔记
5. 根据表现建议下一个练习主题或模式
